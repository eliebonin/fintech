# Swap Booking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user explicitly selects delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Book approved OTC autocall-referencing swaps with notional and a governed signed swap-value quote, without generating cash entries.

**Architecture:** Extend the product booking flow and approved conventions, with swap-specific reference validation in a focused module. Persist one trade and immutable BOOKED evidence; history exposes entry reference value, while existing P&L remains fail-closed.

**Tech Stack:** Python, FastAPI/Pydantic, SQLAlchemy/PostgreSQL/Alembic, Decimal; Next.js 16.3.4, React 19, TypeScript, Vitest and generated OpenAPI contracts.

## Global Constraints

- One swap trade; no automatic cash trade, obligation or payment table.
- Quantity unit NOMINAL; price basis SWAP_VALUE_PER_NOTIONAL; quoteFactor is a positive divisor with no default.
- Booking and future MD quotes describe swap value per notional in the same currency and holder orientation.
- Prices may be finite, signed or zero, within existing decimal storage limits.
- OTC TOTAL_RETURN swaps referencing approved autocalls first; existing governed definitions only, not a general swap-creation wizard.
- Funding terms are inherited read-only; no settlement-date requirement or default.
- Preserve tenant isolation, annotations, immutable history and old idempotency behaviour.
- Lightweight unit tests first; robust integration/browser/full-suite verification after the working slice.
- No valuation, payment processing, reset/dividend engine or independently booked cash-event UI.

## Review Focus

1. Zero and negative quotes must not be rejected, treated as missing, or converted to payment directions (Tasks 1, 4).
2. SELL must reverse nominal orientation without also reversing the entered quote (Tasks 1, 3).
3. Shared swap visibility must not leak inaccessible underlying/rate/schedule details (Tasks 2, 3).
4. A funding/reference change after review must block submission, including when quote convention is unchanged (Tasks 2, 3).
5. Separate cash entries must not be generated by replay or by legacy consideration rendering (Tasks 3, 4).
