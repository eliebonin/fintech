# Structured-note P&L implementation plan

> **For agentic workers:** Use superpowers:executing-plans sequentially. Preserve the user's existing feature checkout and unrelated changes; no subagents or automatic commits/pushes.

**Goal:** Enable supplied-price P&L for currently bookable fully funded structured notes, with explicit quotation/interest handling and recorded monetary flows.

**Architecture:** Extend immutable booking normalization and the existing security position/FX bridge. Match source note quotation dimensions to frozen unit/nominal, denomination, divisor and CLEAN/DIRTY/NONE conventions. CLEAN positions may add supplied earned interest and assessed accrued-stock FX; DIRTY/NONE positions retain all-in marks without adding those components again. Reuse retained inputs, economic-flow bookings, ordinary staging/amendments/publication and inspection.

**Tech stack:** Python Decimal, SQLAlchemy/PostgreSQL, FastAPI, React/Next.js.

**Spec:** The design and constraints below implement the user's 28 October agreement to focus on the vital valuation-run path and defer lifecycle functionality.

## Design and constraints

- Use whole-note marks; never reapply embedded leverage, underlying returns or funding models.
- Support NOMINAL and UNITS, percentage or monetary prices, listed/OTC identities, shorts, new trades and manual ordinary sales. Confirmed zero prices are valid; unknown is not zero.
- Add explicit CLEAN note convention. NONE remains its existing no-separate-accrual convention; DIRTY contains accrued interest. Select matching source quote basis. Unlike bases cannot be mixed without assessed conversion evidence; no price-heuristic relabelling.
- Preserve original booking evidence and recover only uniquely fingerprint-bound historical version identities, following the futures adapter pattern.
- Supplied CLEAN daily interest is optional by default. Extend the existing canonical-interest register; do not classify notes as bonds or infer conditional/memory coupons.
- For CLEAN note stock FX, use supplied assessed balance anchors. Do not fabricate full coupon/payment history. Reuse typed retained balance evidence with a bounded schema guard extension; unavailable stock/FX is partial, never zero.
- DIRTY/NONE quote paths do not independently add the same daily interest or accrued-stock FX. Unpaid detached-coupon receivables are not generated by this slice.
- Recorded COUPON income is permitted for canonical structured notes under an explicit recognition role; preserve bond COUPON payment-only behavior. Operations owns economic-date/classification correctness; never generate income from schedules or cash-balance changes. Detect an explicit overlapping CLEAN daily-interest/coupon-income input rather than silently double counting it.
- No lifecycle dashboard, automatic barrier/autocall evaluation, generated redemption/physical delivery, accounting or pricing model. Existing booking maturity constraints remain unchanged; consume valid existing manual closures.
- Keep tenant/strategy/source rights, information-cutoff evidence, exact arithmetic and publication controls.

## Review focus

1. Nominal already contains denomination; unit percentage bookings apply it exactly once.
2. Source and execution quote basis must be compatible, including zero-price observations and original versions.
3. Canonical CLEAN interest must not duplicate across listings or leak into DIRTY/bond processing; mixed bases need explicit coverage treatment.
4. Coupon INCOME versus PAYMENT_ONLY must retain immutable classification and old bond guards at both booking and replay.
5. Missing optional interest/stock must not abort other valid P&L; changed sources still require recalculation before publication.
